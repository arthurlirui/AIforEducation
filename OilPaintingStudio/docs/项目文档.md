## 1. 项目定位

OilPaintingStudio 解决"如何让静态油画动起来"这一 AI + 艺术教育问题, 提供两条互补的技术路线:

| 管线 | 输入 | 输出 | 范式 | 论文 |
|------|------|------|------|------|
| **video** | 文本主题 | 多镜头油画风格叙事短视频 | LLM 剧本驱动, 多镜头, 无 3D | (Canvas3D §讨论 提及, 非 §3.7) |
| **revive** | 单幅油画 + 手绘线稿 | 可探索的油画风格动态视频 | 物体级 3D + 线稿重排, 有 3D 几何 | **Canvas3D 主稿** (IJCAI'26) |

两管线共享 ComfyUI HTTP 客户端、配置系统、ffmpeg 工具等基础设施 (在 `common/` 子包). 论文方面, Canvas3D 把 revive 的 4 模块架构作为主体贡献, video 管线在讨论章节作为"生成 + 动画整合"的工程方向之一被提及.

## 3. 管线 1: video — 剧本驱动多镜头短片

### 3.1 流程

```
LLM 剧本 (OpenAI 兼容 API, JSON 输出, 失败回灌 ≤3 轮)
  → ComfyUI 关键帧生成 (img2img_oilpaint 模板, 实为 txt2img: EmptyLatentImage + denoise=1.0)
  → ComfyUI I2V 视频 (LTX-Video 快 / Wan2.2-I2V 高质量, 逐镜头切换)
  → ffmpeg 自动剪辑 (normalize → concat → BGM 情绪匹配 + 字幕烧录)
```

### 3.2 模块清单

| 模块 | 文件 | 职责 |
|------|------|------|
| `screenplay/schemas.py` | pydantic 模型 `Script`→`Scene`→`Shot`, 含 `StylePreset` | 剧本结构 |
| `screenplay/prompts.py` | 系统提示词, **从镜头提示中排除风格词**, 风格从预设确定性注入 | 风格×内容解耦 |
| `screenplay/generator.py` | `generate_screenplay(theme, settings)`, 解析失败自动回灌重试 ≤3 轮 | 剧本生成 |
| `pipeline/director.py` | `run_full` 全链路编排, 分 `stage_generate` / `stage_render` / `stage_compose` | 导演 |
| `pipeline/keyframe.py` | 关键帧生成, 调用 `img2img_oilpaint` 模板, **denoise=1.0 实为 txt2img** | 关键帧 |
| `pipeline/animate.py` | I2V 动画, 按 `shot.video_model` 选 LTX 或 Wan, 逐镜头切换 | 动画 |
| `pipeline/edit.py` | ffmpeg: normalize → concat → BGM 情绪匹配 + 字幕烧录 | 剪辑 |
| `pipeline/ffmpeg_tool.py` | ffmpeg 定位 (从 conda 查找) | 工具 |
| `mesh2video/` | 风格×几何解耦: 单张风格图 + depth/clay 序列 → 风格化视频 (trimesh + imageio) | 扩展 |
| `audio/bgm.py` | BGM 情绪匹配 (按剧本情绪选 BGM) | 音频 |
| `audio/tts.py` | **TTS stub** — 旁白仅以字幕形式烧录, 无真实语音合成 | 音频 |
| `cli.py` | click CLI: `health` / `generate` / `render` / `compose` / `full` | 入口 |

### 3.3 配置 (`common/config.py::Settings`)

`Settings` dataclass 含 video 管线全部字段: 画幅 (9:16 / 16:9), 时长, fps, 并发数, SDXL checkpoint, oilpaint LoRA (强度 0.8), LTX (steps 30, cfg 1.0), Wan (steps 30, cfg 6.0), 输出目录. 风格预设库在 `styles.yaml` (印象派 / 巴洛克 / 现实主义 / 浪漫主义, 每个含 painters 列表 + positive_prefix + negative prompt + sampler / scheduler / cfg / steps + bgm_mood).

## 4. 管线 2: revive — 单画物体级 3D 重排动画 (Canvas3D)

### 4.1 流程 (Canvas3D 4 模块)

```
单幅油画 P + 手绘线稿 {ℓ_i}
  → PaintParse (stage1): YOLO 分割 + Depth Anything V2 深度 → K 个前景实例 + 背景
  → MonoSplat (stage2): TripoSplat 单图→3DGS + 度量重缩放 → 3DGS 物体库
  → SketchComp (stage3): 线稿轮廓配准 (IoU + Chamfer, Adam) + SD 修复 → 重排场景
  → ArtiFlow (stage4+5): 多视角关键帧渲染 + 双 ControlNet (depth 0.85 + HED 0.6) → 视频
```

### 4.2 模块清单

| 模块 | 文件 | 职责 | 关键实现 |
|------|------|------|----------|
| **PaintParse** | `stage1/segment.py` | YOLO 实例分割 | YOLOv8-seg; **fallback**: K-Means + 连通域 + 底部三分之一人像 mask |
| | `stage1/depth.py` | Depth Anything V2 单目深度 | **fallback**: 垂直梯度 + 亮度合成深度 |
| | `stage1/parse_control.py` | 控制信号解析 | 解析 `ControlSignals` |
| **MonoSplat** | `stage2/triposplat.py` | TripoSplat 单图→3DGS + 度量重缩放 | `λ_i = d_i · h_i^px / f`; **fallback**: 深度反投影 mock 3DGS (TripoSplat 导入必抛 ImportError) |
| | `stage2/gs2d_init.py` | 3DGS→2DGS 转换 | surfels_to_ply / depth_to_pointcloud; 真实 2DGS 优化需外部仓库 |
| | `stage2/assemble.py` | `GSModelRegistry` 模型管理 | 注册 + 查询 3DGS 物体库 |
| **SketchComp** | `stage3/lineart_parse.py` | 线稿解析 | Canny [50,150] 提取外部轮廓; 线稿可选 (auto-Canny fallback) |
| | `stage3/reposition.py` | 轮廓配准 | `L = 1 - IoU + λ_c·Chamfer`, λ_c=0.3; **实现**: 贪心 hill-climb (非 Adam 梯度, 无可微渲染) |
| | `stage3/inpaint.py` | 遮挡修复 | **实现**: OpenCV Telea/NS (非 SD); seamlessClone 失败回退 alpha blend |
| **(stage4)** | `stage4/__init__.py` | 多视角关键帧渲染 | `run_keyframe_generation`: 相机弧形插值 + surfel 投影 + 深度排序; Canny 边缘; **手绘关键帧线稿叠加是死代码** (未接通) |
| **ArtiFlow** | `stage5/__init__.py` | 视频合成编排 | Wan2.2 / LTX2.3 双路径; **ComfyUI 路径调用 `client.free_memory()` (不存在) → 总是触发 mock fallback** |
| | `stage5/workflow.py` | ComfyUI 工作流构建 | `build_wan_workflow`: ControlNet strength `depth_guide_strength` / `edge_guide_strength`; **Wan 采样器误用 `ltx_steps`/`ltx_cfg` (复制粘贴 bug)**; `build_ltx_workflow`: IC-LoRA + Union Control |

### 4.3 数据模型 (`revive/schemas.py`)

`ObjectCategory` (枚举: person/animal/building/plant/vehicle/object/background), `SegmentedObject` (mask, bbox, depth_range, category), `GSModelRecord` (gaussians, label, scale), `GSModelRegistry` (注册/查询), `Stage1Output`/`Stage2Output`/`Stage3Output`/`Stage4Output`, `RepositionTransform` (theta, t, s), `KeyframeSpec` (rgb/depth/edge 路径), `ControlSignals`.

### 4.4 配置 (`config/revive_settings.yaml`)

Revive 配置独立于 video, 在 `config/revive_settings.yaml`. 含: 画幅/fps/时长, YOLO 模型 + 置信度/IoU 阈值, Depth Anything V2 模型, 物体类别→深度范围映射, TripoSplat 模型 + 焦距 + 每物体高斯点数, 2DGS 仓库路径, 边缘对齐迭代数 + 学习率, 线稿阈值, 修复半径 + 方法, ControlNet 引导强度 (depth/edge/rgb), LTX IC-LoRA + 分辨率.

**注意**: `common/config.py::Settings` dataclass **不包含** revive 字段. revive 代码引用 `settings.yolo_model` / `settings.depth_guide_strength` 等字段时, 需要从 `revive_settings.yaml` 单独加载 (当前 `config.py::load_settings` 默认加载 `settings.yaml`, revive 需扩展或单独加载逻辑).

revive 管线设计为"真实模型不可用时自动降级, 保证全链路可测试":

## 6. 论文初稿

### 6.1 Canvas3D (IJCAI'26 主稿)

**位置**: `paper/Canvas3D/`
**标题**: *Canvas3D: Object-Level 3D Gaussian Splatting and Line-Art Composition for Painting Animation*
**编译**: `main.pdf`, 10 页, 89 条参考文献, XeLaTeX + BibTeX
**章节**: intro / related / method / experiment / conclusion (5 节; **discussion 章节存在但未被 main.tex 引入**)

**摘要**: 把静态艺术品 (油画/水墨/壁画) 动画化为可探索、叙事连贯的视频. 现有方法两极分化: I2V 扩散模型运动流畅但视角变化下 3D 结构崩塌; 3D 重建 (NeRF/3DGS) 保留几何但破坏笔触纹理. Canvas3D 整合 4 模块: PaintParse (YOLO 分割 + Depth Anything V2 深度) + MonoSplat (TripoSplat 单目 3DGS 提升 + 度量重缩放) + SketchComp (手绘线稿轮廓配准 + 深度修复) + ArtiFlow (多视角关键帧 + 双 ControlNet 视频扩散, Wan2.2 或 LTX2.3).

**4 模块与代码映射**:

| 论文模块 | 方法节 | 代码位置 | 关键公式 |
|----------|--------|----------|----------|
| PaintParse | §3.1 | `revive/stage1/` | YOLOv8-seg + LoRA r=16; Depth Anything V2 ViT-L; 层分配用深度 10/90 百分位 |
| MonoSplat | §3.2 | `revive/stage2/` | `λ_i = d_i · h_i^px / f` (度量重缩放); TripoSplat 预测 N_i 个 3D 高斯 |
| SketchComp | §3.3 | `revive/stage3/` | `L_cont = 1 - IoU(R, Γ) + λ_c·Chamfer(∂R, Γ)`, λ_c=0.3; Adam 50 步 lr 1e-2; SD-Inpainting + depth CN strength 0.75 dilation 8px |
| ArtiFlow | §3.4 | `revive/stage4/` + `revive/stage5/` | T=8N+1 关键帧; `c_t = s_d·c_t^depth + s_e·c_t^edge`, s_d=0.85, s_e=0.6; Wan2.2 cfg 6.0 30 步 1280×720 / LTX2.3 cfg 1.0 30 步 768×512; 首帧锚定 `σ_t = 0.02·|t-1|`; 每物体运动验证 IoU < 0.75 触发重排 |

**实验**:
- 数据集 PaintingAnim-50: 50 张经典画 (30 油画 + 15 水墨 + 5 壁画), 35 训练 / 15 测试, 每张 5-15 个实例 mask + 3-5 套手绘线稿
- 6 baselines: Wan2.2-I2V / LTX-Video-I2V / AniClipart / 2DGS+bilinear / OilPaintingRevive / LivePortrait (人像子集)
- 5 metrics: CLIP-I / LPIPS / FID-VID / Disocclusion PSNR / Composition IoU

**主结果** (Table 1):

| 方法 | CLIP-I↑ | LPIPS↓ | FID-VID↓ | PSNR↑ | IoU↑ |
|------|---------|--------|----------|-------|------|
| Wan2.2-I2V | 0.79 | 0.35 | 28.4 | — | — |
| OilPaintingRevive | 0.83 | 0.31 | 22.8 | — | — |
| **Canvas3D** | **0.86** | **0.28** | **18.3** | **29.1** | **0.81** |

**用户研究** (Table 3, 25 参与者): Canvas3D 艺术真实性 4.31/5, 运动自然度 4.05/5, 构图意图 4.48/5; 偏好率 82% / 76% / 88%.

**消融** (Table 2, 8 变体): 去掉 TripoSplat (→2DGS) CLIP-I -10.5% FID-VID +52.5%; 去掉 depth CN FID-VID +78.1%; 去掉轮廓配准 IoU 从 0.81 崩到 0.41 (-49.4%).

**限制**: (i) 逐帧 ControlNet 2D 投影, 极端视角 (>60°) 产生幻觉纹理; (ii) TripoSplat 单图重建对严重遮挡退化; (iii) 颜色修复假设局部相似纹理, 稀疏构图大遮挡失败; (iv) 物体串行处理.

**重要订正**: 早期文档称 Canvas3D 有"§3.7 互补剧本驱动管线"描述 OilPaintingVideo — **实际不存在**. 当前 method.tex 仅 §3.1-3.6 (4 模块 + Pipeline Algorithm). OilPaintingVideo 仅在 discussion 章节被提及, 而 discussion 未被 main.tex 引入.

### 6.3 InkFlow (IJCAI'27 初稿)

**位置**: `paper/InkFlow/`
**标题**: *InkFlow: Dual-Conditioned Video Diffusion for Chinese Ink-Wash Painting with Five-Level Ink Theory*
**核心思路**: 中国水墨画受五级墨色理论 (焦浓重淡清) 与留白约束. InkFlow 用双条件微调 Wan2.1-I2V: (1) 线分布图 `C_line` 在去噪前半段注入 (管结构, 模拟勾皴→渲染流程); (2) 墨密度分布图 `C_ink` (5 通道, 每级一通道) 在后半段注入 (管色调). 三项艺术特定损失: `L_ink` (Earth Mover's Distance 匹配 5 级墨色直方图) + `L_blank` (留白区局部方差惩罚, "计白当黑") + `L_rhythm` (笔节奏时序先验, 抑制高频抖动保留低频"呼吸"运动). 总损失 `L = L_diff + 0.5·L_ink + 0.3·L_blank + 0.2·L_rhythm`. 适配器为轻量 ControlNet 分支 (~5M 参数). 基于 OilPaintingVideo 的 ComfyUI I2V 基础设施.
**章节**: 6 节 (introduction / related / method / experiments / discussion / conclusion), 12 条参考文献

## 8. 已知问题与限制

### 8.1 代码层面

1. **`revive/cli.py` 导入不存在的 `run_pipeline`**: 第 13 行 `from ..video.pipeline.director import run_pipeline`, 但 `video/pipeline/director.py` 只定义 `run_full` (及 `stage_generate` / `stage_render` / `stage_compose`), 无 `run_pipeline`. **`oilrev run` 命令会在模块加载时 ImportError**. 临时方案: 直接调用 `revive.stage1.run_segmentation` 等模块函数. 长期: 写独立 `revive/pipeline/director.py`.
2. **`revive/stage5/__init__.py` 调用 `client.free_memory()` (不存在)**: `ComfyClient` 无此方法 → 总是触发 `AttributeError` → 被 `except Exception` 捕获 → **总是走 mock fallback**, ComfyUI 真实路径实际从未执行.
3. **`revive/stage5/workflow.py` Wan 采样器误用 LTX 参数**: `build_wan_workflow` 的采样器 steps/cfg 用 `settings.ltx_steps` / `settings.ltx_cfg` (复制粘贴 bug), 应为 `settings.wan_steps` / `settings.wan_cfg`.
4. **`revive/stage3/reposition.py` 用贪心 hill-climb 非论文的 Adam**: 论文描述 Adam 50 步 lr 1e-2 优化 `L_cont`, 代码实现是贪心边缘 IoU hill-climb (无可微渲染, 无梯度).
5. **`revive/stage3/inpaint.py` 用 OpenCV Telea/NS 非论文的 SD-Inpainting**: 论文描述 SD-Inpainting + depth ControlNet strength 0.75, 代码实现是 OpenCV Telea/NS.
6. **`revive/stage4` 手绘关键帧线稿叠加是死代码**: `run_keyframe_generation` 中 `if i < len(stage3.__pydantic_fields__)` 块永不触发.
7. **`video/pipeline/keyframe.py` 负面提示注入无效**: `build_keyframe_workflow` 把 `inputs.negative` 注入负面节点, 但负面节点用 `inputs.text` (字段名不匹配).
8. **`common/config.py::Settings` 不含 revive 字段**: revive 代码引用 `settings.yolo_model` / `settings.depth_guide_strength` 等需从 `config/revive_settings.yaml` 单独加载, 当前 `load_settings` 默认加载 `settings.yaml`.

### 8.2 论文层面

1. **Canvas3D discussion 章节未被 main.tex 引入**: `sec/discussion.tex` 存在但 `\input` 列表只有 intro/related/method/experiment/conclusion. 若要包含需加 `\input{sec/discussion}`.
2. **Canvas3D 图变体待选**: `figures_preview/` 有 15 TikZ + 15 Draw.io 图变体 (V2, 2026-10-13 relayout), 等用户挑选后才能集成进 `sec/method.tex`.
3. **InkFlow 仅为初稿**: 6 节 LaTeX 框架 + method 节有核心公式, experiments 章节内容待补.

### 8.3 环境

- 本机 scipy 1.x 与 numpy 2.x 二进制不兼容 (`_ARRAY_API not found` / `numpy.dtype size changed`), 影响 mesh2video 测试 (依赖 trimesh → scipy.sparse). 与 DotArtKit 同一已知问题.
