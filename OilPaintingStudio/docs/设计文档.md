### 1.2 整合动机

两个项目存在三重关联与割裂:

1. **技术互补, 共享 IJCAI 论文**: OilPaintingVideo 是"文本→叙事多镜头短片"管线; OilPaintingRevive 是"单画→物体级 3D→线稿重排→动画"管线. IJCAI'26 论文 **Canvas3D** 把 Revive 架构作为主体, Video 作为 §3.7 的"互补剧本驱动管线"章节. 论文要求两者代码统一引用.

3. **共享资源**: 18 张经典油画扫描件 (`images/`)、ComfyUI workflow 模板、IJCAI'26 LaTeX 模板被两项目共同引用. 整合后资源单一存放点.

### 1.3 整合目标

- **单一 Python 包** `oilpainting_studio`, 两个管线作为子包 `video/` 与 `revive/`, 共享 `common/`
- **保留两个 CLI 入口**: `oilpainting-studio video ...` 与 `oilpainting-studio revive ...` (或直接 `from oilpainting_studio.video.cli import cli`)
- **论文初稿整合**: Canvas3D (主稿 IJCAI'26) + 调研综述 (备份) + InkFlow (IJCAI'27 中国水墨) 统一放 `paper/`
- **保留全部测试**: 32 + 20 = 52 项测试迁入 `tests/`, 命名加 `video_` / `revive_` 前缀避免冲突
- **保留全部资产**: config / workflows / assets (bgm + fonts) / 18 张名画 / ComfyUI 模板 / ffmpeg 工具
- **统一设计文档**: 本文档作为整合后的权威设计依据

## 2. 统一视角: 油画动态生成的两条管线

两个项目解决"如何让静态油画动起来"的两种互补范式:

### 2.1 OilPaintingVideo — 剧本驱动多镜头短片

```
LLM 剧本 (OpenAI 兼容 API)
    → ComfyUI txt2img 油画关键帧 (img2img_oilpaint 模板, denoise=1.0 实为 txt2img)
    → ComfyUI I2V 视频 (LTX-Video 快 / Wan2.2-I2V 高质量, 逐镜头切换)
    → ffmpeg 自动剪辑 (normalize → concat → BGM 情绪匹配 + 字幕烧录)
```

特点: 文本叙事驱动, 多镜头, 风格预设库 (印象派/巴洛克/现实主义/浪漫主义), 9:16 与 16:9 双画幅.

### 2.2 OilPaintingRevive — 单画物体级 3D 重排动画 (Canvas3D)

```
单幅油画 + 手绘线稿
    → PaintParse (stage1): YOLO 分割 + Depth Anything V2 深度 → K 个前景实例 + 背景
    → MonoSplat (stage2): TripoSplat 单图→3DGS + 度量重缩放 → 3DGS 物体库
    → SketchComp (stage3): 线稿解析 + 轮廓配准 (IoU + Chamfer, Adam 50 步) + SD 修复
    → ArtiFlow (stage5): 多视角关键帧渲染 + 双 ControlNet (depth 0.85 + HED edge 0.6) + Wan2.2/LTX2.3 视频合成
```

特点: 单画物体级 3D, 线稿引导重排, 几何×风格解耦, 每物体运动验证 (SAM2 mask IoU).

### 2.3 论文中的关系

Canvas3D 论文 (`paper/Canvas3D/main.tex`) 把 Revive 的 4 模块作为主体方法, Video 作为 §3.7 的互补管线. 关键技术细节:
- Video 的 LLM system prompt 从镜头提示中排除风格词, 风格从预设确定性注入
- Video 的关键帧生成实为 txt2img (EmptyLatentImage, denoise=1.0), 非 img2img
- Video 的相机运动基于文本提示 (非几何); Revive 的 mesh2video 提供显式风格×几何解耦
- Video 的转场已配置但未实现 (硬拼接); TTS 为 stub (仅字幕)

## 4. 模块详细设计

### 4.1 `common/config.py` — 3 层配置

**职责**: 加载 `.env` + `settings.yaml` + `styles.yaml` 三层配置.

**来源**: 迁自 `OilPaintingVideo/src/oilpaint/config.py`. Revive 的配置在 `config/revive_settings.yaml` 单独存放 (因两管线配置项不同, 合并到一个 yaml 会混乱).

**关键设计**: `PROJECT_ROOT` 指向 `OilPaintingStudio/` 包根, `config/` 目录下的 yaml 通过 `PROJECT_ROOT / "config" / "settings.yaml"` 加载.

### 4.2 `common/llm_client.py` — OpenAI 兼容 LLM 客户端

**职责**: OpenAI 兼容 API 调用 (retry / timeout / JSON mode). 模式参考自 `story-studio` 项目.

**仅 video/ 使用**: revive 不用 LLM (输入是单画 + 手绘线稿, 非文本).

### 4.3 `common/comfy/` — ComfyUI HTTP 客户端

**职责**: 两管线共享的 ComfyUI 交互层.

- `client.py` — queue / poll / download, 信号量并发, 错误 + 超时处理
- `workflows.py` — 模板加载 + 深路径参数注入 (按节点 id)
- `templates/` — 5 个 API 格式 JSON 工作流:
  - `img2img_oilpaint.json` — Video 关键帧 (节点 id: ckpt/lora/latent/prompt_pos/prompt_neg/sampler/save)
  - `ltx_i2v.json` / `wan_i2v.json` — Video I2V (LTX 快 / Wan 高质量)
  - `ltx_i2v_3d_guide.json` / `wan_i2v_3d_depth.json` — Revive 的 3D 引导 I2V

**节点 id 约定** (必须一致, 参数注入依赖): 见 `docs/comfyui_http_api.md`.

### 4.4 `common/utils/` — 工具函数

- `ffmpeg_tool.py` — ffmpeg 定位 (从 conda 查找, 因本机 ffmpeg 不在 PATH)
- `image.py` — 图像工具 (迁自 revive)
- `vram.py` — VRAM 管理 (迁自 revive)

### 4.5 `video/` — OilPaintingVideo 管线

**子模块**:
- `screenplay/` — LLM 剧本: pydantic schemas (Script→Scene→Shot) + 系统提示 (风格词排除) + 生成器 (解析失败自动回灌, ≤3 轮)
- `pipeline/` — 导演编排: `director.py` 全链路, `keyframe.py` 关键帧 (txt2img), `animate.py` I2V (LTX/Wan 逐镜头切换), `edit.py` ffmpeg 剪辑, `ffmpeg_tool.py`
- `mesh2video/` — 风格×几何解耦: 单张风格图 + depth/clay 序列 → 风格化视频 (trimesh + imageio)
- `audio/` — BGM 情绪匹配 + TTS (stub, 旁白仅字幕)
- `cli.py` — click CLI: `health` / `generate` (剧本) / `render` (关键帧+I2V) / `compose` (剪辑) / `full`

**关键实现细节** (论文 §3.7):
- LLM system prompt 从镜头提示中排除风格词, 风格从预设确定性注入
- 关键帧生成实为 txt2img (EmptyLatentImage, denoise=1.0), 非 img2img
- 逐镜头 I2V 模型选择: Wan 用于高运动镜头, LTX 用于效率
- 转场已配置但未实现 (硬拼接)

### 4.6 `revive/` — OilPaintingRevive 管线 (Canvas3D 4 模块)

**子模块**:
- `schemas.py` — pydantic 数据模型: `SegmentedObject`, `GSModelRecord`, `GSModelRegistry`, `Stage1Output`...`Stage3Output`, `RepositionTransform`, `KeyframeSpec`, `ControlSignals`
- `stage1/` PaintParse — `segment.py` (YOLO 分割), `depth.py` (Depth Anything V2), `parse_control.py`
- `stage2/` MonoSplat — `triposplat.py` (单图→3DGS + 度量重缩放 `λ_i = d_i·h_i^px / f`), `gs2d_init.py` (3DGS→2DGS + surfels_to_ply), `assemble.py` (GSModelRegistry)
- `stage3/` SketchComp — `lineart_parse.py`, `reposition.py` (轮廓配准 `L = 1 - IoU + λ_c·d_Chamfer`, Adam 50 步 lr 1e-2), `inpaint.py` (SD 修复 + depth ControlNet strength 0.75, dilation 8px)
- `stage4/` 多视角关键帧渲染 (T=25, 8N+1 约束)
- `stage5/` ArtiFlow — `workflow.py` (双 ControlNet: depth 0.85 + HED edge 0.6; Wan2.2-A14B cfg 6.0 30 步 1280×720 或 LTX2.3 cfg 1.0 30 步 768×512; 首帧 latent 锚定 σ_t = 0.02·|t-1|)
- `cli.py` — click CLI

**Fallback mock**: SAM2 / DA-V2 / R³ / ComfyUI 不可用时自动降级, 保证流程可测试.

**Revive CLI 的特殊依赖**: 原 `oilrev/cli/main.py` 引用 `..pipeline.director` (即 oilrev 自己的 pipeline), 但 Revive 的 pipeline 实际就是 stage1-5 编排, 没有独立的 `pipeline/` 目录. 迁移脚本已把 `..pipeline.director` 重写为 `..video.pipeline.director` — **这是一个已知的整合妥协**, 实际运行时 Revive CLI 不应依赖 Video 的 director. 见 §10.1.

## 8. Canvas3D 论文 4 模块数学公式

详细推导见 `paper/Canvas3D/sec/method.tex`, 此处仅列核心公式.

### 8.1 度量重缩放 (MonoSplat)

```
λ_i = (d_i · h_i^px) / f
```
其中 `d_i` 是物体深度, `h_i^px` 是物体在图像中的像素高度, `f` 是焦距.

### 8.2 轮廓配准损失 (SketchComp)

```
L_contour = 1 - IoU(R, Γ_i) + λ_c · d_Chamfer(∂R, Γ_i),  λ_c = 0.3
```
其中 `R` 是渲染轮廓, `Γ_i` 是目标线稿轮廓, `∂R` 是轮廓边界.

### 8.3 双 ControlNet 组合 (ArtiFlow)

```
c_t = s_d · c_t^depth + s_e · c_t^edge
```
其中 `s_d = 0.85` (depth), `s_e = 0.6` (HED edge).

### 8.4 首帧 latent 锚定

```
z_1' = z_1 + σ_t · ε,  σ_t = 0.02 · |t - 1|,  ε ~ N(0, I)
```

## 10. 已知限制与未来方向

### 10.1 已知限制

1. **Revive CLI 对 Video pipeline 的依赖**: 原 `oilrev/cli/main.py` 引用 `..pipeline.director`, 但 Revive 没有独立 pipeline 目录. 迁移脚本把它重写为 `..video.pipeline.director`. 实际运行 Revive CLI 时这会失败 (Video 的 director 期望 LLM 剧本输入, 与 Revive 的单画输入不兼容). **临时方案**: Revive 用户应直接调用 `stage1.run_segmentation` 等模块函数, 而非 CLI. **长期方案**: 为 Revive 写独立的 `revive/pipeline/director.py` 编排 stage1-5.
2. **ComfyUI 模板部分重叠**: Revive 原 `oilrev/comfy/` 与 Video 的 `oilpaint/comfy/` 有重叠模板. 整合后取 Video 版本 (模板更全, 含 3D 引导), 但 Revive 的 `ltx_iclora_workflow.json` 在 `revive/stage5/` 保留.
3. **两管线配置未合并**: `config/settings.yaml` (Video) 与 `config/revive_settings.yaml` (Revive) 分开存放, 因配置项差异大. `common/config.py` 默认加载 `settings.yaml`; Revive 需单独加载 `revive_settings.yaml` (可能需调整 `config.py` 支持参数指定).
4. **论文图表变体待选**: Canvas3D 的 15 TikZ + 15 Draw.io 图变体 (V2, 2026-10-13 relayout) 在 `paper/Canvas3D/figures_preview/`, 等用户挑选后才能集成进 `sec/method.tex`.

### 10.2 未来方向

1. **统一 director**: 为 Revive 写独立 `revive/pipeline/director.py` 编排 stage1-5, 消除对 Video pipeline 的依赖
2. **统一配置**: `common/config.py` 支持按管线加载不同 yaml (`--profile video` / `--profile revive`)
3. **共享 3D 引导 I2V**: Revive 的 `ltx_i2v_3d_guide.json` 与 Video 的 `ltx_i2v.json` 可统一为带可选 depth 输入的单模板
4. **Web UI**: Streamlit / Gradio 统一界面, 两管线 tab 切换
5. **InkFlow 论文扩展**: InkFlow (IJCAI'27 中国水墨) 目前仅有初稿, 可复用 Canvas3D 的双 ControlNet 框架扩展到水墨风格
