# 傅里叶纹样 GUI 编辑器设计（fcp.gui v1.0）

> 模块: `src/fcp/gui/` · 日期: 2026-11-11 · 状态: 已实现, 69 测全绿, 7 张实操截图全部验收通过
> 定位: 论文 Demo 软件——"图片加载 → OpenCV 预处理 → 傅里叶分解 → 封闭线条填色"完整工作流

## 1. 总体架构

tkinter 桌面应用（零额外依赖、Windows 开箱即用），沿用 DotArtKit 波点编辑器
验证过的模式：**GUI 回调只做状态搬运，可测试逻辑全部下沉为纯函数模块**。

```
src/fcp/gui/
  imio.py      cv2 中文路径兼容层（np.fromfile + imdecode）
  pipeline.py  预处理纯函数管线: BGR → 灰度 → 模糊 → 阈值 → 形态学 → 掩膜
  fill.py      填色状态 (FillState) + 渲染 (render_fill) + 传统调色板
  app.py       tkinter 主体 (PatternApp): 工具栏/参数面板/画布/状态栏
```

UI 布局::

    +------------------------------------------------------------+
    | 工具栏: 打开图片 | 应用预处理 | 傅里叶分解 | 视图单选 | 导出  |
    +----------------+-------------------------------------------+
    | 参数面板        |  画布（原图/掩膜/线条/填色 四视图切换）     |
    |  OpenCV 预处理  |                                           |
    |  傅里叶分解     |                                           |
    |  填色          |                                           |
    +----------------+-------------------------------------------+
    | 状态栏: 部件数 / 自动阶数集合 / 耗时                          |
    +------------------------------------------------------------+

## 2. 功能与工作流

### 2.1 图片加载
- `imio.imread_`：`np.fromfile + cv2.imdecode` 绕开 Windows cv2 中文路径
  限制（与 OilPaintingStudio common/imio.py 同源模式）；读失败/空文件/
  不存在统一返回 None，弹错误框。
- 加载时最长边限缩到 1024px（性能保护）。

### 2.2 OpenCV 预处理（pipeline.py, PreprocessParams 单一事实来源）
GUI 可调项 → 管线步骤：

| GUI 控件 | 参数 | 说明 |
|---|---|---|
| 反色勾选 | `invert` | **白底黑线稿必须勾**（线条成为前景） |
| 阈值模式下拉 | `thresh_mode` | manual / **otsu** / adaptive |
| 手动阈值滑块 | `threshold` | manual 模式生效 |
| 模糊方式+核 | `blur_kind, blur_ksize` | none / gauss / median，去扫描噪点 |
| 开运算核滑块 | `morph_open` | 去小白噪 |
| 闭运算核滑块 | `morph_close` | 补小缝 |
| **孔洞填充勾选** | `fill_holes` | **线稿工作流关键**（见 §4 坑①） |
| （内部） | `max_side` | 加载限缩 |

### 2.3 傅里叶分解
- 复用 `decompose_mask`（连通域 → Moore 轮廓 → 每部件自动选阶）；
- 面板可调：最大阶数（Spinbox）、误差阈值 px（Spinbox）；
- **全局阶数覆盖滑块**：0=每部件自动阶数；>0 强制全部件同一 K——
  论文 demo 的核心交互（拖动滑块现场演示"谐波阶数 ↔ 形态细节"）。

### 2.4 封闭线条填色（fill.py）
- `FillState`：调色板名 / 渲染模式（lines/fill/both）/ 阶数覆盖 /
  单部件颜色覆盖列表 / 背景 / 线宽；
- 5 套传统调色板：敦煌 / 青花 / 朱砂 / 水墨 / 七彩；
- **点击改色**：填色视图下点击部件 → 射线法命中测试 → 系统选色器；
- `render_fill`：与 fcp 渲染同坐标体系（内容自适应缩放居中 + 超采样），
  both 模式描边自动用同色系加深（HLS 变换）。

### 2.5 导出
- 填色 PNG（1024px，imio 不需要——PIL.save 支持中文路径）；
- PatternSpec JSON（每部件颜色写入 spec，直接对接 L1/LLM 层）。

## 4. 实现踩坑记录

1. **闭运算填不了线稿的大洞**：线稿描边围合的区域是几十像素的洞，
   闭运算只能补 ≤核尺寸的缝；正确做法是 **flood-fill 孔洞填充**
   （从四角把外部背景标成哨兵值，剩余背景即孔洞）。首版实现还把
   哨兵值错设为 0（与目标同值导致孔洞被丢弃），必须用非 0/255 的
   哨兵（如 100）再 `ff != 100`。
2. **tkinter 坑复现**（DotArtKit 记忆）：`canvas.height()` 不存在须用
   `winfo_height()`（未布局时返回 1，要 max(1, ...)）。
3. **ImageGrab 时序坑**：`app.update()` 单帧后窗口未实际绘制，
   连续 ImageGrab 抓到同一帧屏幕 → 视图内容截图改为直接保存
   `_current_image()` 渲染结果；完整 UI 截图须 `after()` 调度进
   mainloop 真实绘制后再抓。
4. **PrintWindow 抓被遮挡窗口**：ImageGrab 抓屏幕区域，窗口被
   其他窗口遮挡时抓到的是遮挡帧。改用 Win32 `PrintWindow`
   （`PW_RENDERFULLCONTENT=2`）直接抓窗口自身位图，被遮挡也正确。
   注意 **`GetBitmapBits` 返回 BGR 序 + 自底向上行序**：须先
   `[::-1]` 倒行再 `[:, :, ::-1]` 换通道，否则红蓝互换（橙色
   #d35400 显示成蓝色 #0054d3，肉眼极易误判为"改色未生效"）。
5. **测试素材几何**：线稿腐蚀出描边要求部件间隙 > 2×线宽；"放大几何
   保持画布"会让部件越界粘连——应"放大画布保持几何"。
6. driver 模板拼接：内嵌 Python 源码里 f-string 的 `{x}` 会被外层
   `.format()` 当占位符，driver 内禁用花括号字面量。
7. **改色后必须显式刷新**：直接改 `fill_state.part_colors` 不会触发
   画布重绘，须调用 `_refresh_view()`；导出渲染与画布显示是两条路径，
   只改状态再截图会得到旧帧。

## 5. 与论文 Demo 的对接

- 现场演示脚本：打开线稿 → 勾反色+孔洞填充 → 分解 → 拖"全局阶数"
  滑块从 K=3 到自动（谐波收敛的直观展示）→ 切调色板 → 点击改色 →
  导出 PNG/Spec；
- gui_spec.json 即三层管线 L1 的目标格式：后续 LLM 生成 PatternSpec
  后可直接在本 GUI 中渲染预览（双向闭环）；
- 每部件的自动阶数 + RMS 记录在 Decomposition.report()，可直接进
  论文的量化表格。
